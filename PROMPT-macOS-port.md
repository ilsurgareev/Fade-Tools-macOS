# Промпт: портирование Fade Tools для macOS

Работай с исходниками из архива `FadeTools-standalone-source-for-Mac.zip`. Это самостоятельное приложение для работы с видеофайлами. Начни разработку macOS-версии на основе включённых исходников и `TRANSFER_NOTES.md`.

## Назначение

Создай самостоятельную macOS-программу для открытия видеофайлов, настройки четырёх независимых Fade, предпросмотра, задания границ In/Out и рендера выбранных отрывков через очередь. Предусмотри отдельный сценарий пакетной обработки видеофайлов через FFmpeg/FFprobe droplet, если он укладывается в архитектуру macOS-версии.

## Жёсткая граница продукта

Программа работает только с видеофайлами как самостоятельное приложение. Не добавляй интеграцию с DaVinci Resolve: ни API, ни скрипты, ни кнопки для управления Resolve, ни применение Fade к таймлайну, ни запуск или управление рендерами Resolve. Не добавляй другие Resolve-специфичные функции.

## Работа с исходниками

Сначала прочитай `TRANSFER_NOTES.md`, затем изучи `settings_entry.py`, `settings_app.py`, `clip_window.py`, `clip_plan.py`, `clip_engine.py`, `media.py`, `config.py`, `live_fade.py`, `frame_time.py` и связанные тесты. Считай эти исходники описанием текущего поведения, но проверяй детали по коду и тестам. Не переносите вслепую Windows-специфичные вызовы и пути; выбери подходящие macOS-решения, сохраняя пользовательские сценарии и защитные проверки.

Сохраняй важные гарантии текущего приложения: не перезаписывать исходник или неизвестный существующий результат, отклонять неподдерживаемые входные медиа явно, не публиковать частичный файл, проверять подготовленный результат до публикации, сохранять состояние ожидающей очереди и корректно отменять только принадлежащие приложению процессы предпросмотра/подготовки. Настройки и временные файлы размещай в подходящих пользовательских каталогах macOS. Не включай бинарники Windows из других комплектов.

Сохрани назначение модулей и структуру там, где это разумно; если архитектуру нужно изменить, сначала объясни причину и покажи целевую структуру. Не теряй существующие проверки и тестовое покрытие. Отдельно проверь зависимости, работу Qt Multimedia, расположение FFmpeg/FFprobe, drag-and-drop, воспроизведение, очередь после перезапуска и безопасную публикацию результатов на macOS.

## Порядок работы

1. Проведи аудит исходников и платформенных зависимостей, составь краткую карту текущих сценариев и предложи план переноса.
2. Затем реализуй macOS-вариант в отдельной рабочей копии/ветке, не повреждая исходный Windows-комплект.
3. Запусти доступные автоматические проверки и практические проверки на macOS. Не заявляй проверку, которую фактически не выполнял; перечисли оставшиеся ограничения.
4. В конце дай краткое описание изменений, способ запуска для разработки на macOS и результаты проверок. Не добавляй инструкции по Windows-сборке, если они не нужны для сравнения поведения.

Если для безопасного продолжения не хватает сведений, сначала сообщи, что именно выяснил из исходников, и задай только необходимые вопросы. Не подменяй реализацию одним планом: после аудита продолжай работу над портом в рамках доступного окружения.
